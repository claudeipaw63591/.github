<p>团队用 Claude 到第三个月，常见的情况是：账号从 3 个涨到 20 个，出口从 1 条变成十几条，谁在用哪条、哪条快到期、哪个项目占了几个并发，全靠聊天记录里一张临时表格维持。一旦有人休假，接手的人得先问一圈才知道哪条线不能动。这篇把住宅 IP 资源管理拆成项目、账号、成员三层，每层给出可落地的字段、检查动作和交接办法，目标是让一个新同事看着台账就能接手。</p>

<h2>一、先把手上的东西清点成一张台账</h2>
<p>管理这件事的起点不是工具，是"你现在到底有什么"。不少团队以为自己在用 8 条住宅出口，清点完发现是 11 条，其中 3 条是试用期送的、2 条已经欠费但还挂在配置里。这些"幽灵资源"最容易在排查时误导人。</p>
<h3>台账至少要有六列</h3>
<p>出口地址含端口、所属地区、类型（静态／动态／独享）、计费方式、到期时间、当前绑定账号。这六列缺一列，后面就会有一次"这条线是谁的"的追问。再加一列备注写清采购渠道和工单号，出问题时能直接报给服务商，不用翻邮箱。</p>
<h3>每两周对一次账，别等出事才对</h3>
<p>对账动作很简单：拿服务商后台的资源列表，和本地台账做一次差集。多出来的（后台有、台账没有）通常是有人临时开的；少掉的（台账有、后台没有）是已经释放但配置没删的。后者更危险，它会让健康检查一直报错，而错误现象看起来像是网络问题。</p>

<h2>二、项目这一层决定出口池的边界</h2>
<p>按项目分池的意义不是好看，而是把故障影响面框住。一个项目的出口被限速，不该顺带把另一个项目的日常访问拖下水。分池粒度不必很细，通常一个项目 2 到 4 条出口就够，条数多了反而难维护。</p>
<h3>两种常见分法，按重要性或按地区</h3>
<p>业务重要性分法：核心项目单独一个池，非核心项目共用一个池。地区分法：按访问目标所在地分池，美东、欧洲、亚太各一组。前者管可用性，后者管访问自然度，两个目标别混在一次划分里，否则两边都不彻底。</p>
<h3>跨项目借用要走登记，不能口头借</h3>
<p>临时借用很常见——某个项目要跑一次批量任务，从隔壁池借两条线。允许借，但要在台账里写清借用人、借出时间、预计归还时间。没登记的借用是资源混乱的主要来源，因为归还往往被忘掉，借出方还以为资源在自己手上。</p>

<h2>三、账号与出口的绑定关系写成一对一</h2>
<p>同一个账号长期在两三条出口之间跳，是很多异常提示的起点。绑定写成一对一之后，排查路径会短很多：账号异常时先看它绑的那条线最近有没有变更，而不是从十几条线里猜。</p>

<h3>允许一对多，但要写清理由</h3>
<p>确实有一对多的合理场景，比如同一个账号的网页端和 API 端需要不同地区出口。这种情况在台账里单独标注"多出口·已审批"，并记录每个出口对应的用途。没有标注的一对多，默认按配置错误处理。</p>
<h3>解绑比绑定更需要流程</h3>
<p>绑定时大家都很谨慎，解绑往往很随意——直接把配置删掉，账号就变成"裸奔"状态，下一次登录用的就是本机真实出口。约定一个动作：解绑前先把账号切到备用出口，确认能正常访问，再释放原出口。多花两分钟，少一次意外。</p>

<h2>四、成员权限：看得见和改得动要分开</h2>
<p>资源管理的事故很多不是外部原因，是内部误操作：有人为了测试把生产出口的密码改了，有人清理配置时删掉了一条在用的线。权限分层的核心就是把"能看"和"能改"拆开，让大部分人只能看。</p>
<h3>三种角色基本够用</h3>
<p>查看者能看台账和状态但不能改；操作者能改自己负责项目的绑定；管理员能增删资源、改计费项。三个角色覆盖绝大多数团队，再细就容易变成没人愿意维护的权限表，最后人人都是管理员。</p>
<h3>操作留痕记到什么粒度</h3>
<p>至少记四要素：谁、什么时候、对哪条资源、做了什么动作（新增／绑定／解绑／改配置）。不必记具体参数值，但要能回答"这条线昨天为什么断了"这类问题。日志保留三个月通常够覆盖一次完整排查周期。</p>

<h2>常见问答</h2>
<h3>小团队只有三五个账号，需要这么细的台账吗？</h3>
<p>答：可以简化成一张表，但六列字段别省。账号少时靠记忆还能撑，一旦有人加入或临时加开账号，缺字段的表会立刻失效。先用最小版本，账号超过十个再拆成两张。</p>
<h3>资源到期提醒用什么方式比较可靠？</h3>
<p>答：别只依赖服务商的邮件。在台账里加到期日一列，用一个每天跑一次的脚本比对，剩余七天和剩余一天各提醒一次，提醒发到项目群而不是个人邮箱。人换了，提醒还在。</p>
<h3>动态出口也要写进台账吗？</h3>
<p>答：要，但字段可以少。记录池的入口地址、地区范围、并发上限和计费口径即可，不必记录每一个轮换出来的地址。重点是能算出这个池被谁在用、每月大概花多少。</p>
<h3>怎么判断一条资源该回收了？</h3>
<p>答：看三个信号：连续三十天没有绑定账号、绑定的账号已停用、同类出口还有两条以上空闲。满足任意两条就可以进入回收流程，回收前先标"待回收"，观察一周没人认领再释放。</p>
